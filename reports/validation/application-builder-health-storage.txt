Application Builder health storage visibility
============================================

Implemented
-----------
- /health retains status=ok and the reunia/application-builder service list.
- /health now includes application_builder storage metadata:
  - workflow_storage: memory
  - application_storage: sqlite
  - durability: demo-only
  - multi_worker_safe: false
  - multi_node_safe: false
- The payload is generated by the canonical application_builder_storage_status()
  helper in products/resume_taylor/app.py.
- No database path, credentials, tokens, keys, environment values, or claimed
  infrastructure scale are exposed.
- Deployment documentation includes the exact JSON response and clarifies that
  this metadata does not detect actual Gunicorn workers or Lightsail scale.

Validation
----------
- Modified Python files compile successfully.
- Focused health/persistence/Lightsail contracts: 16 passed, 0 failed.
- Full unittest discovery: 64 total, 50 passed, 14 skipped, 0 failed.
- Dependency-aware final checks passed all available suites; full Flask and
  Playwright suites remain blocked because flask, redis, openai, and xlrd are
  unavailable in the validation environment.
- A runtime /health assertion is included in
  tests/integration/test_application_builder.py and will execute when those
  optional runtime dependencies are installed.
